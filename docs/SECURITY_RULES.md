# Security and fairness guardrails

1. **No secret keys in Git or client bundles.** `NEXT_PUBLIC_` environment values are public. The `OPENAI_API_KEY` and service-role database key remain server-only.
2. **All sensitive operations authenticate AND authorize on the server.** Verify user through `getUser`, role from protected `profiles.role`, and ownership of the attempt. Never trust the browser to indicate administrator status or the student ID.
3. **RLS is defense in depth.** Migrations intentionally do not give the browser INSERT/UPDATE rights over attempts, results, tasks, events. Server-only service client is dangerous: explicitly validate every action before using it.
4. **One real attempt per student and task** (current project spec). Expired or technically invalidated attempts need an exception process that is reviewed, not automatically a cheating conviction. Model request and DB writes must be idempotent.
5. **Integrity events are only signals.** Device permissions may be unavailable or misreported; use distinct `invalidated` vs suspicion/review labels. Never publicly name people as cheats, auto-reset progress, or use media-based conclusions as sole ground for punishment.
6. **Media stays on device.** Webcam tracks/frames are never uploaded or stored. No microphone permission. If multi-face detection is added, only non-identifying event type/time reaches the backend; do not record face landmarks/embeddings.
7. **Screen API is limited.** Some browsers do not implement Window Management API, some require explicit permission. Supported browser requirement must be explained upfront and tested in a real HTTPS session. Cannot detect every device or an out-of-view phone.
8. **Show the limitations of AI marking.** Code is read, not executed. The AI must treat student submissions as untrusted text, not follow embedded instructions. Grade only via task rubric; no invented execution results.
9. **Public profile:** only opted-in student profile visible. Published passed score summary can be shared when is_public=true via the restricted `public_student_result_cards()` RPC; full theory/practical/understanding answers and feedback are visible only with explicit share_submission=true through `public_student_submission_detail()` RPC. Raw attempts/results are owner-only RLS. Failed attempts and warning history are private.
10. **POPIA:** gather clear notice/consent, limit retention, add deletion/contact mechanism, keep data at rest secure, inspect third-party processor terms and region. Seek proper local legal review before a production launch.
