### 1.Entelect

**What "work ready" means to them**
Grads who can operate in a real SDLC: understand requirements, write clean code, collaborate, communicate, and accept feedback. Their Boot Camp explicitly trains and assesses these, not just raw coding speed.

**Task format**
- Online application → screening → interviews (often with group/open-day activities)
- Many candidates report an initial technical test, then panel interviews
- Successful grads go through an 8–10 week Boot Camp with team projects and code reviews

**Tools/platforms used**
Not clearly named in public materials. Candidates mention a "technical test" and group coding tasks, but no specific platform (HackerRank/CoderPad/etc.) is confirmed for grads.

**Generic vs company-specific**
Early technical tests seem fairly general CS/programming. The Boot Camp is explicitly real-world and enterprise-tech focused (multiple languages, full SDLC, code reviews).

**How they verify answers are genuine**
- In-person/virtual interviews and group tasks
- Boot Camp projects are scrutinised and code-reviewed by Tech Leads

**What's missing/frustrating (candidate view)**
Limited detailed public feedback; small sample on Glassdoor. Some candidates feel the process is relatively short and light on deep algorithmic screening.

**Would they want a third-party, company-specific task + verification tool?**
Moderately likely. They already invest in structured assessment and graduate training. A tool mirroring their Boot Camp style (real-world tasks + integrity checks) could fit, though they may prefer to keep assessment inside their own Boot Camp.

**Example question themes**
- Technical: basic algorithms/data structures, debugging, small coding tasks
- Behavioural: teamwork, handling feedback, dealing with ambiguous requirements

### 2.Dariel Solutions

**What "work ready" means to them**
Determined, CS/IT-aligned grads who can grow quickly into professional software engineers. Emphasis on fundamentals, problem-solving, and attitude more than deep specialisation at entry.

**Task format**
- Online application via Ditto → additional info for shortlisted candidates → panel review → interviews → offers
- For non-grad software devs, OfferZen lists a take-home coding game (2 weeks–1 month) then a 2–2.5h technical interview with architects/seniors. Unclear if grads get the same coding game.

**Tools/platforms used**
Application via Ditto. The coding game platform isn't publicly named.

**Generic vs company-specific**
Not clearly stated. Given their bespoke software work, the coding game could be tailored, but there's no explicit confirmation.

**How they verify answers are genuine**
- For roles with a coding game: a long technical interview with architects/senior devs who probe your solution
- For grads: verification leans on interviews and panel scrutiny of background and mindset

**What's missing/frustrating (candidate view)**
Very limited public candidate reviews. Process seems opaque outside the high-level steps; no clear recurring complaints found, but also little transparency.

**Would they want a third-party, company-specific task + verification tool?**
Possibly. They already use a take-home coding game plus deep tech interviews for some roles, showing they value realistic tasks and thorough vetting.

**Example question themes**
- Technical: core programming, problem-solving, possibly a coding game task
- Behavioural: motivation for software engineering, teamwork, handling pressure

### 3.Luno

**What "work ready" means to them**
How you work, think, and approach problems, plus alignment with their "Moontality" values (ownership, humility, moving fast, learning). They want people who can apply skills in practice, not just recite theory.

**Task format**
- Application → screening call → take-home assignment + presentation → face-to-face/panel interviews (often multiple rounds)
- Some roles also include a Bryq psychometric test

**Tools/platforms used**
Take-home assignment platform not explicitly named in public docs.

**Generic vs company-specific**
Described as putting "your ideas and/or technical skills into practice." Likely at least partly tailored to role (backend/crypto/data), but not explicitly confirmed.

**How they verify answers are genuine**
- Presentation of the take-home solution
- Multiple technical/behavioural interviews where they deep-dive into your approach, trade-offs, and code

**What's missing/frustrating (candidate view)**
Some candidates report generic rejections with little feedback after investing significant effort in the take-home.

**Would they want a third-party, company-specific task + verification tool?**
Quite likely. They already rely on take-home + presentation and care about practical problem-solving. A tool with better integrity signals and structured rubrics could address feedback/complaint issues.

**Example question themes**
- Technical: HackerRank-style problem (e.g., "find the missing number in an array 0–10"); system design question
- Behavioural: "Describe a time you had conflict in a team and how you handled it"; situational questions around ownership, failure, and learning

### 4.Yoco *(SA sources only)*

**What "work ready" means to them**
Technical depth (algorithms, system design, code quality) plus impact orientation (translating financial concepts for small businesses), ownership, and leadership behaviours.

**Task format**
- Recruiter screen → coding screen (LeetCode-style, timed) → system design → onsite/loop coding (harder problems) → behavioural/leadership round
- Process can run 4–8 weeks; onsite may be 1–2 days

**Tools/platforms used**
SA descriptions mention "coding screen" and "onsite coding" but don't explicitly name HackerRank/CoderPad.

**Generic vs company-specific**
SA candidate reports mention problems with domain flavour (e.g., merchant transactions, Yoco-specific scenarios), suggesting some company-specific framing, but core is still algorithmic/DS.

**How they verify answers are genuine**
Multi-round live interviews (coding + system design + behavioural) after the initial screen.

**What's missing/frustrating (candidate view)**
Limited detailed SA complaints; Glassdoor SA shows mixed difficulty ratings but generally professional experience. Main implicit frustration is length (4–8 weeks) and intensity of the loop.

**Would they want a third-party, company-specific task + verification tool?**
Moderately likely. They already run a rigorous, multi-round technical loop with domain-flavoured problems, but may prefer to keep control over their existing loop design.

**Example question themes**
- Technical: LeetCode-style medium/hard problems (arrays, graphs, DP, concurrency); system design for a payments/merchant service (scaling, idempotency, retries)
- Behavioural/leadership: "Tell me about a time you took ownership of a critical incident"; "Describe a disagreement with a teammate and how you resolved it"

### 5.Takealot *(SA sources only)*

**What "work ready" means to them**
Solid technical skills, cultural fit, and ability to handle e-commerce scale/complexity. Their grad programme is a 3-month hands-on course to turn grads into production-ready engineers.

**Task format**
- Application → recruiter screen → technical/skill assessment (coding challenge or technical task, ~1–2 hours) → multiple final interviews (technical + behavioural)
- Some roles: online HackerRank test plus onsite technical interviews

**Tools/platforms used**
SA candidate reports explicitly mention HackerRank for online coding tests (2 problems + MCQs, ~1.5 hours).

**Generic vs company-specific**
HackerRank tests appear to be standard algorithmic problems; interviews then probe experience and e-commerce scenarios.

**How they verify answers are genuine**
Follow-up onsite/panel technical interviews with seniors, who dig into your thinking and past projects.

**What's missing/frustrating (candidate view)**
Some SA candidates describe the process as "simple" or agent-mediated; others note it's demanding but fair. Usual take-home/online-test frustrations (time vs feedback) may apply.

**Would they want a third-party, company-specific task + verification tool?**
Quite likely. They already use HackerRank and run a structured multi-round process. A tool creating Takealot-specific e-commerce tasks (cart, inventory, logistics scenarios) with integrity features could improve signal and candidate experience.

**Example question themes**
- Technical (HackerRank-style): 2 coding problems (arrays/strings/data structures) + MCQs; occasional domain-flavoured tasks (orders, inventory, optimisation)
- Behavioural/technical: "Describe a project where you had to balance multiple priorities"; questions about tech stack, debugging approach, past e-commerce/high-traffic systems
